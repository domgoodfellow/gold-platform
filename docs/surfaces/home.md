# Organization Home surfaces

Workspace and feature surface specifications. System-wide rules, including **Core rules**, are in [docs/ui-system.md](../ui-system.md). Before changing a surface here, check `docs/decisions/` for ADRs that name it.

## Global Home

Global Home uses the shared `DashboardLayoutGrid` with a fixed product layout and no database preference writes, `MetricTile` overview figures, a compact attention list, `ViewNav` URL controls and the shared Finance payment-trend projection with `Chart`. Every Home panel is content-sized (`sizing: 'content'`): it takes the height of what it holds, reserves no empty footprint and stretches neither to fill the workspace nor to match a taller panel beside it; only the payment chart keeps its compact plot height. The greeting/date header keeps Quick actions and browser-local Customize when optional panels have relevant content. Its date line ends with the refresh control, which shows when Home was last read; there is no separate refresh row and no second Search entry (the sidebar's Search row is the one Search). At most four meaningful authorized overview figures are shown, followed by the current Contacts total and current receivables; when none is positive, kernel CRM/Work figures retain truthful zeros instead of filling the row with unrelated workspace zeros. A figure of zero is shown as 0; a figure from a source that failed is omitted, never shown as zero. Overview figures are organization-wide, current, and independent of attention scope and the Business performance period, so no tile carries a "Now" line. Tiles share one size: equal columns that fill the row, and equal height within a row.

## Needs attention and obligations

Needs attention leads, prioritized from actual overdue and urgency facts. It is a compact list with one row per record: the title is the row's only control and the whole row is its target; beneath it, the source, business context and the holder; on the right, the record's own status (a Work stage, a Case, conversation or inquiry status) and Overdue, Urgent or High when they apply, above any deadline (Due, or Starts for Work). The read that owns each record classifies it as a task (ordinary work: CRM tasks, Cases, conversations, calls, invoices, unscheduled or unassigned Work), a review (a decision waiting: Agent approvals, inquiries awaiting review, a website revision submitted for publication review) or a problem (something failed, conflicts or is misconfigured: coverage and availability conflicts, failed rules, deliveries and Agent interactions, agents not answering, rules with no action, campaigns with no form source); each kind has its own icon and name. Overdue means an explicit deadline has passed; a record's age or last activity never makes it overdue. Studio drafts still being edited (website revisions and Form drafts) stay in Studio and are not attention items; only a website revision in publication review is. All/Mine/Urgent/Overdue are URL-backed, as are the Business performance period and Today/Upcoming obligation view (`schedule`). Category totals come from exact source counts and may overlap; previews are labelled and bounded. Bounded configuration checks retain a link to the complete source and do not claim an all-clear result. Work coverage and availability exceptions use W3's complete `workOperations` projection, including exceptions outside the displayed schedule preview, and link to Dispatch's matching date/resource/assignment context. Unscheduled staffing and unassessed time availability are separate. My priorities appears only for distinct assigned responsibilities not already in attention. Dated obligations follow, excluding records already above. Home places a commitment overlapping Today only in Today; Upcoming covers all seven local dates after Today, including the seventh, and excludes the eighth. All-day and continuing commitments carry explicit labels. The displayed obligation preview is bounded and links to the complete authorized source views; those links remain when all previewed records were already shown above.

## Business performance and activity

Business performance follows obligations and contains the period-based authorized source metrics and signed payment series, with stored currencies kept separate. Its Today/Last 7 days/This month control affects performance only; current receivables and contact totals sit in the overview instead. The panel is shown only when there is at least one period figure (a zero included) or Finance is unavailable, in which case it says so; it is never an empty frame. Recent activity takes half the row beside Business performance or obligations and widens to the full row when it is alone. It uses bounded source previews, with the shared event feed covering the last seven local dates independently, keeps the latest event per record and does not repeat operational records already displayed. Irrelevant empty secondary panels are omitted. Per-source failures remain unknown, their figures are omitted and healthy sources stay visible; an activity-only failure is identified without discarding a healthy operational summary. Work shape/resource prerequisite failures are isolated to Work. Failed and uncertain Automation deliveries remain separate facts with exact state-filtered links. The existing route loading skeleton is retained, and refresh keeps the current view with an explicit busy state. Narrow containers, including an open Agent rail, use the same shared responsive grammar.

## Customize

Customize retains `gildops:home:v1:{organizationId}:{membershipId}` in this browser for the performance/activity selections. No database layout format is introduced. A refused storage write reports that the preference could not be saved and retains the saved selection. Core operational information is not hideable.

## Quick actions and Search

Quick actions and the organization command palette consume one authorized action list. Actions are grouped by workspace and open owning creation surfaces; invoices open the existing Finance workflow through its collection create query. Search is a command palette opened from the sidebar's Search row, which matches the other primary controls in size and state; it has no keyboard shortcut and no visible shortcut hint. It offers create actions, authorized workspace destinations and supported Agent prompts. The AI workspace manages assistants; the header Agent opens the global conversation rail. Home, Search and Library form one sidebar cluster. Account footers show a saved personal name when available and the organization role.

## Setup status

Setup is onboarding status, not navigation, and Home carries no setup banner. While the business is in SETUP the organization header shows one compact Setup control (`features/setup/setup-status.tsx`), read from `computeSetupOverview` (`lib/application/setup/status.ts`): its accessible name and badge give the number of required blockers only, so recommended and optional areas never block launch. Choosing it opens a popover (keyboard, touch, Escape returns focus) that reads the overview again and shows the required steps remaining, the areas-ready progress and a link to the Setup page: Review setup, or Review and launch once nothing is required. Someone who cannot launch sees the same facts with View setup and a note that an organization manager can finish setup or launch; nothing else changes for them. A failed read says the status is unavailable and offers Try again. The control is not shown on live businesses, in Platform, on personal account pages or on the Setup pages themselves, and it disappears once the business launches. It never opens by itself. The organization switcher carries a quiet "Setup pending" line beneath the business name while setup is open. The checklist, optional recommendations and launch controls stay on the Setup page, and launch uses the existing server-checked command. The shell has no notification bell or notification dialog. Configuration notifications follow the canonical configuration target's workspace and deduplicate repeated messages. Read failures remain unavailable, and configuration never implies live provider operation. Published website status uses a neutral success presentation even when draft changes also exist. Optional performance/activity panels have browser-local, actor-and-Organization-scoped preferences; core operational panels are not hideable.
